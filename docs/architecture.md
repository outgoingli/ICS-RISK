# 系统结构与研究边界

本系统针对已有 LevelSP 写请求，完成执行前约束评估。第一版不预测液位轨迹，不计算事故概率，不把约束结果强行合并为一个安全分数。图谱本身也不证明规则正确。

## 模块

| 模块 | 输入 | 输出 | 责任 |
|---|---|---|---|
| `ics_risk/graph_build` | 人工审定的节点边 JSON、证据索引和原始文件 | 已校验图版本 | 结构、引用、证据字节一致性；显式发布 |
| `ics_risk/graph_query` | 点位、图版本、JSON 或 Neo4j 后端 | 语义对象、回路、适用约束、依赖和查询路径 | 读取固定版本，错误不自动回退 |
| `ics_risk/quantification` | 已核实约束参数与解析出的操作数 | 偏差、余量、间隔、条件匹配及逐项状态 | 纯计算，不访问数据库或控制设备 |
| `lvsp_eval/engine.py` | command、snapshot、history、graph_version | 判定、逐项结果、证据、完整性 | 组合查询、输入校验和计算，保留已有验证语义 |
| `lvsp_eval/adapter.py`、`replay.py` | 独立执行框架的请求及原始采集记录 | 规范评估输入 | 不下发指令，不修改已有保护与恢复 |
| `ics_risk/service.py`、`web/` | HTTP 请求 | 中文展示、评估接口 | 只提供查询与评估 |
| `ics_risk/records.py` | 每次评估输入与结果 | 独立 UUID 记录 | 追加保存，不覆盖历史 |

`lvsp_eval` 保留兼容入口；实际四种计算模板维护在独立的 `ics_risk.quantification` 中。

## 一次评估的数据流

```text
已审定知识 + 证据 -> 构建校验 -> 显式发布 Neo4j 固定版本
                                    |
请求 + 原始观测 + 历史 -> 读取该版本完整图快照
                         -> 点位语义与约束依赖查询
                         -> 证据/数据完整性检查 -> 四种模板计算
                         -> 判定 + 可解释路径 + 独立记录 -> 页面
```

Neo4j 保存真实的节点和关系，不是把整个 JSON 存成一个字符串。一次评估以一个只读查询取回完整版本，经结构和摘要检查后在快照内遍历，避免一次请求在不同版本间漂移。当前不是每一步都在线执行 Cypher，也没有自动关系推理。

## 图与数值分离

图只有 Component、Point、Variable、ControlLoop、Constraint 五类节点，EXPOSES、MAPS_TO、HOSTED_BY、IN_LOOP、APPLIES_TO、REQUIRES 六类关系。Neo4j 额外保存字符串 scope/version/hash 元数据用于隔离和追溯，不增加领域节点类型。

数值、阈值、地址和缩放在图外 `bindings.json` / `constraints.json`；实测值、时戳、历史作为每次评估的输入。候选值不能覆盖当前实测值。参数必须有来源和类别，未核实规则不能启用。

## 判定

- `BLOCK`：存在已核实且计算失败的约束；仍分别报告其他未知项。
- `INDETERMINATE`：缺失规则参数、证据、状态、图路径或数据库不可用，无法完成预定评估。
- `ALLOW`：在当前已声明且完整核实的约束范围内全部通过；不等于物理安全证明，更不是下发指令的授权。

真实 LevelSP 第一版的最小操作间隔尚无核实参数，因此其他四项通过时仍返回 `INDETERMINATE`。不能用采样周期、保持时长或猜测的秒数补齐。

## 后续研究工作

下一步需核实操作间隔及任务要求的来源、接入具有完整时间与来源信息的采集/操作历史、用独立实验验证约束的效果，再决定是否增加过程模型或综合风险量化。新增方法必须有自己的输入契约、适用范围和验证集。当前代码提供扩展边界，不声称已经完成这些研究。
